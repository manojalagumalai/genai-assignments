How to use the reviewer

Two input modes available inside the chat panel on the right.

  1. Choose your input mode — switch between JIRA Ticket (fetches the story from Jira automatically) and Paste Story (review any text directly).

  2. Enter your story — type a JIRA key like SCRUM-1, or paste a full user story. Use the sample below for a fund-transfer template.

  3. Click Review — the AI evaluates Clarity, Completeness, Business Value, Testability, and Technical Feasibility, each scored out of 20.

  4. Read the report — the response is formatted as an HTML table with scores, overall rating, and specific improvement areas.

  5. Copy the output — use the 📋 Copy button on each response or Copy All in the header to grab all text.

Quality dimensions evaluated

Each dimension contributes 20 points to the overall quality score.

# Dimension What is evaluated
① Clarity Is the story unambiguous and easy to understand for all stakeholders?
② Completeness Are acceptance criteria, preconditions, and edge cases well-defined?
③ Business Value Does it reflect tangible value (patient safety, compliance, efficiency)?
④ Testability Can QA engineers derive test cases directly from the acceptance criteria?
⑤ Technical Feasibility Is it practically implementable within typical healthcare/banking system constraints?

📋 Sample User Story — Fund Transfer

A realistic banking story ready for review. Copy it or paste it directly into the chat.

User Story: Fund Transfer Title: As a registered bank customer, I want to transfer funds between my own accounts or to external beneficiaries, so that I can make payments and manage my finances securely. Description: A logged-in customer must be able to initiate domestic and international fund transfers via the online/mobile banking portal. The system must enforce validation, security checks (OTP), and provide real-time status feedback. Preconditions: - Customer is authenticated via username + password (2FA required for high-value transfers) - Source account has sufficient available balance - Beneficiary is either pre-registered or being added for the first time (new beneficiary requires OTP verification and a 24-hour cooling-off period) Acceptance Criteria: AC-01: Given the user is authenticated, when they open "Transfer Funds", all eligible source accounts with current available balances are displayed. AC-02: When the user enters a transfer amount, the system validates: amount > 0, amount ≤ available balance, and amount ≤ single-transfer limit ($10,000). AC-03: When the user enters beneficiary details, the system validates the account number format and checks whether the account exists in the payment network. AC-04: For amounts above $500, an OTP is sent to the registered mobile number and must be verified within 5 minutes before the transfer is processed. AC-05: When all validations pass and the user confirms, the transfer is processed within 30 seconds; a unique reference number is generated, the balance is updated immediately, and a confirmation email/SMS is sent. AC-06: When a transfer fails for any reason, a descriptive error message is displayed (e.g., "Insufficient funds", "Invalid account number"), and no deduction is made from the source account. AC-07: All transfer attempts (successful or failed) are recorded in the audit log with timestamp, actor ID, amount, source account, destination account, and outcome. Business Rules: - Maximum single transfer: $10,000 - Daily cumulative transfer limit per customer: $25,000 - International transfers require prior KYC verification - Recurring/scheduled transfers must be cancellable at least 2 hours before execution - Transfers to new beneficiaries are subject to a 24-hour cooling-off period for fraud prevention Edge Cases: - Transfer to the same account as source - Two concurrent transfers that together exceed the daily limit - Transfer attempted with an expired or already-used OTP - Network timeout during the confirmation step - Transfer to a beneficiary account that has been closed or suspended
